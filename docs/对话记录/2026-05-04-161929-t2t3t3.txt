● 修复说明

  根因

  langchain4j 的 @SystemMessage(fromResource=...) 注解会把 prompt 文件内容过
  PromptTemplate.apply(variables)。这个引擎扫到任何 {{xxx}}
  都当成"必需的待注入变量"。我在 prompt 例子里写的 {{age}} {{operationDate}}
  {{lengthOfStay}} 等 —— 这些是 业务模板占位符（V1 schema 里 R001/R002 的
  error_message_template 就是这种语法），不是给 langchain4j
  注入的。generate(String naturalLanguage) 方法签名上没有 @V("operationDate")
  参数提供值，引擎就抛了 Value for the variable 'operationDate' is missing。

  改法

  绕开 AiServices：
  - RuleDslGenerator 改成普通接口，去掉 @SystemMessage 注解
  - LlmAutoConfiguration.ruleDslGenerator() 启动时把 prompt
  文件当字面字符串读出来，用 SystemMessage.from(rawText) +
  UserMessage.from(naturalLanguage) 直接调 ChatLanguageModel.generate(messages)
  —— 不经任何模板引擎，{{xxx}} 原样保留传给 Gemini

  没受影响

  - prompt 文件内容不变（占位符照用）
  - RuleDslGenerator 接口签名不变 → RuleGeneratorService 调用方零改动
  - RuleGeneratorServiceTest mock 在接口层 → 单测不受影响

  重启后验证

  重启后端再试 "年龄小于0逻辑性扣分"，应该能正常拿到 wrapper 输出。
